Punto 01 — Canales Encubiertos en Cabeceras TCP/IP

Protocolo: IP / TCP Capa: Internet / Transporte Criticidad: Medio-Bajo

Descripción de la vulnerabilidad

Manipulación maliciosa de campos de cabecera (IP ID, ISN, TTL) para transmitir datos ocultos sin alterar la carga útil visible.

Escenario de laboratorio

Emisor 10.9.0.101 codifica mensaje en IP ID; receptor 10.9.0.102 decodifica con Scapy.

Mitigación aplicada

Normalización de cabeceras: ISN pseudoaleatorio (RFC 6528) y IP ID secuencial limpio en el receptor.

Estado vulnerable

Estado mitigado

Vulnerable

El receptor extrae el mensaje oculto codificado en el campo IP ID de los paquetes ICMP/TCP enviados por el emisor.

Mitigado

Tras aplicar normalización de cabeceras, el campo IP ID ya no conserva el mensaje codificado; la extracción falla o devuelve ruido.

Comandos de demostración

docker compose up --build && docker compose exec emisor python3 /lab/encode_headers.py 10.9.0.102 SECRETO

Punto 02 — Timing Covert Channels

Protocolo: TCP / UDP Capa: Transporte Criticidad: Bajo

Descripción de la vulnerabilidad

Modulación de intervalos entre paquetes (IPD) para transmitir bits sin modificar cabeceras ni payload.

Escenario de laboratorio

Emisor 10.9.0.101 envía ICMP con retardo corto/largo; receptor 10.9.0.102 mide tiempos.

Mitigación aplicada

Jammer con tc netem que añade jitter uniforme destruyendo la señal temporal.

Estado vulnerable

Estado mitigado

Vulnerable

El receptor decodifica correctamente la secuencia de bits a partir de los intervalos entre paquetes.

Mitigado

Con jitter activo en el gateway, la decodificación por temporización produce errores o secuencia inválida.

Punto 03 — TCP Session Hijacking Off-Path

Protocolo: TCP Capa: Transporte Criticidad: Alto

Descripción de la vulnerabilidad

Inyección off-path de segmentos TCP aprovechando side-channels de Challenge ACK (CVE-2016-5696).

Escenario de laboratorio

Servidor 10.9.0.5, cliente 10.9.0.6, atacante 10.9.0.7 en red 10.9.0.0/24.

Mitigación aplicada

sysctl net.ipv4.tcp_challenge_ack_limit=2147483647 en el servidor.

Estado vulnerable

Estado mitigado

Vulnerable

El atacante detecta variaciones en Challenge ACKs al probar números de secuencia, revelando información de la sesión.

Mitigado

Con el límite elevado, las respuestas Challenge ACK son uniformes y el canal colateral deja de filtrar información.

Comandos de demostración

docker compose exec atacante python3 /lab/challenge_ack_probe.py 10.9.0.5 10.9.0.6

Punto 04 — Idle Scan / Zombie Scan

Protocolo: IP / TCP Capa: Internet / Transporte Criticidad: Medio

Descripción de la vulnerabilidad

Escaneo ciego usando IP ID predecible de un host zombie para inferir puertos abiertos sin revelar la IP del atacante.

Escenario de laboratorio

Atacante 10.9.0.100, zombie 10.9.0.150, objetivo 10.9.0.200.

Mitigación aplicada

rp_filter=1 y descarte de paquetes con IP spoofing.

Estado vulnerable

Estado mitigado

Vulnerable

Delta IP ID del zombie indica puerto 80 abierto en el objetivo (incremento de +1).

Mitigado

Con rp_filter activo, los SYN spoofed no alcanzan el objetivo y el delta IP ID no cambia.

Comandos de demostración

docker compose exec atacante python3 /lab/idle_scan.py 10.9.0.150 10.9.0.200 80

Punto 07 — Evasión IDS por Fragmentación IP

Conexiones HTTP incompletas que agotan el pool de threads del servidor web.

Escenario de laboratorio

Atacante 10.9.0.11, servidor Apache 10.9.0.100.

Mitigación aplicada

iptables connlimit --connlimit-above 10 por IP.

Estado vulnerable

Estado mitigado

Vulnerable

Cliente legítimo recibe timeout; servidor satura conexiones concurrentes.

Mitigado

Conexiones extra son rechazadas; cliente legítimo accede con normalidad.
